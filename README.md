# ECE 520/L – Lab 3: BRAM FIFO

**Author: Charbel Abou Afech** 

## Overview

This lab implements a single-clock FIFO in Verilog that uses Block RAM for its memory. The design was checked with a self-checking testbench that uses input data generated by a Python script. The Vivado project is created with a Tcl script, and synthesis was run to confirm the memory uses BRAM.

## Design Summary

The top-level module is sc_fifo. Its parameters are WIDTH (16), DEPTH (32), ADDR_WIDTH (5), ALMOST_EMPTY_THRESHOLD (1), ALMOST_FULL_THRESHOLD (31), and READ_LATENCY (1). ADDR_WIDTH is log2 of DEPTH.

The memory is a 32 x 16 array marked with ram_style = "block" so Vivado places it in BRAM. Writes and reads are in separate clocked blocks, and the read output is registered, so data appears one clock after a read.

A write only happens when wr_en is high and the FIFO is not full. A read only happens when rd_en is high and the FIFO is not empty. Writing while full or reading while empty is ignored. If wr_en and rd_en are both high, both happen and the count stays the same. If the FIFO is full, only the read happens, and if it is empty, only the write happens.

A count register goes up by one on a write and down by one on a read. The flags come from this count. Empty is high at 0, full is high at 32, almost_empty is high at 1 or less, and almost_full is high at 31 or more. data_count outputs the count and is 6 bits wide so it can show 0 to 32.

The valid signal goes high in the same clock that the read data appears on dout. READ_LATENCY adds extra register stages to dout and valid. The flags and data_count are not delayed.

srst is a synchronous, active-high reset. It clears the pointers and count, so the FIFO goes back to empty. It also clears valid and sets dout to 0.

## Scripts

generate_fifo_data.py creates 64 random 16-bit words and saves them to sim/input_data.txt.

create.tcl creates the Vivado project for the Zybo Z7-10, adds the design and testbench files, and copies input_data.txt into the simulation folder.

simulate.tcl opens the project and runs the simulation. It is based on the course template, with two changes so the testbench can find input_data.txt at the start of the simulation and so run all stops at the end of the testbench.

## Verification and Results

The testbench tb_sc_fifo uses a 50 MHz clock and an active-high reset. It checks every read and every flag on its own and prints TEST PASSED or TEST FAILED at the end. It also prints the first and last words of input_data.txt (3900 and ecad) to show the file was loaded.

The test cases are:

1. Reset: data is written and read so dout is not 0, then reset is applied with a word still in the FIFO. dout returns to 0 and the FIFO is empty.
2. All 1s and all 0s: the FIFO is filled with 0xFFFF and read out, then filled with 0x0000 and read out.
3. Alternating patterns: the FIFO is filled with 0xAAAA and 0x5555 and read out in the same order.
4. Every memory location: 32 words from input_data.txt fill every address and are read back, then this is repeated with the next 32 words.
5. Status flags: the FIFO is filled one word at a time and emptied one word at a time, and empty, full, almost_empty, almost_full, and data_count are checked after each step.
6. Read and write enables: writing while full is ignored, reading while empty is ignored, both enables while full only reads, both enables while empty only writes, and both enables with data inside does both.

All six tests passed.
